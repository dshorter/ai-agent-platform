Field note

The clip that told no one

A read limit set once, against a file that grew, quietly cost an agent its best source for five days. Nothing failed. That was the problem.

2026-08-11 · ai-agent-platform · ops

On the morning of August 11, our Director agent spent eight of its twelve tool calls on a single file.

Two whole-file reads and six searches, all against the same calendar. Then it hit its step limit and shipped a thin, hedging brief.

The obvious diagnosis is a stuck loop. It isn’t. Every one of those calls succeeded, and every one of them was different.

01 — what it was doing

A join, by hand

The calendar had crossed the read tool’s byte ceiling. The file was 51,100 bytes; the limit was 40,000. A whole-file read returns the first 40,000 bytes and a truncation notice.

11,100

bytes past the ceiling — holding the 8 newest to-dos of 58, three of which the brief went on to cite.

So it went around through search. And search is line-oriented, while a calendar to-do is a record: its title, due date, and status sit on three separate lines, and long descriptions fold across continuation lines.

No single search can return one whole to-do. To reconstruct “what’s overdue and what is it called,” you search once per field and zip the results together by position. Six searches is about what that costs.

02 — call twelve

It solved the problem one move too late

Read the calls in order and you watch it escalate. First the whole-file read, which came back truncated. Then the field-by-field searches, the workaround. Then — and this is the part I keep returning to — one more whole-file read, as though the front door might behave differently the second time.

And then it gave up on the raw file entirely, listed the directory, and opened the assembled view: a page where the joining is already done, generated nightly, sitting right there.

It found that on call twelve. The step limit ended the turn on call thirteen.

And it does not get to keep the insight. The next morning’s run starts cold and walks the same three steps again.

03 — dating it

The degradation has a birthday

Has this always been happening, or is it new? Both halves are checkable. The calendar is version-controlled, so its size over time is a matter of record; every morning run is in the decision log with its call count.

The file crossed 40,000 bytes on August 3. The grinding starts on August 6.

Calls on the calendar, per run0–14, 5, 5, 8, 9, 10

The three-day lag is the honest detail. Right after crossing, only about four to-dos fell off the end, and it could work without them. As the lost tail grew to eight — and as those newest items became the ones that mattered — it had to go get them. The degradation scaled with the size of the loss, which is why it ramped instead of snapping.

Six weeks of a working capability, then a silent stop, with no code change anywhere near it. The trigger was a to-do list getting longer.

04 — the turn

The loud failure is the lucky one

Everything above is the version that announces itself: grinding, limit hits, a cost bump, eventually a brief bad enough that a human notices. We got lucky.

The same defect has a silent form, and the decision log says we have been living with it. Here is every oversized file our agents actually read, over 45 days.

Read the last two columns, not the sizes. Where searches far outrun whole reads, the agent is fighting — visible, expensive, self-announcing. That is the calendar, and that is the project plan.

Now look at the first row. That file was opened eight times, a tenth of it seen, with no follow-up searches, no limit hit, no cost spike, and no hedge in a single reply. It did not fight. It took the first ten percent as the answer.

A confident answer built on a tenth of a file is indistinguishable from a confident answer built on all of it.

The truncation notice was in every one of those eight results. It read the notice and moved on.

One more, quieter still: our newsroom doc carries a marker on line two of its own front matter, read: full — a documented convention meaning read this whole, never conclude from a part of it. It has been seven percent past the ceiling since it crossed. The doc says read it all. The substrate has quietly been unable to.

05 — the irony

The guardrail was the injury

That 40,000-byte ceiling is layer two of a three-layer guard we built on June 29, after a vague instruction sent a search across scraped HTML with single lines up to 731,000 characters. It exhausted memory, and what came back assembled a 3.77-million-token prompt that the API rejected outright.

The guard worked. That failure has never recurred.

What went unwritten is that a clip protects the process and blinds the agent, and only the first half was designed. Six weeks later the guardrail was the injury.

This is not an argument against clipping. It is an argument that a clip is a silent lie by omission unless something checks the size.

06 — the law

Testimony and telemetry

Any limit sized once, against data that grows, becomes a silent capability regression with no alarm. And the agent’s own account of why it stopped is testimony, not telemetry.

Everything needed to catch this was already in the decision log: iteration counts, tool paths, timestamps. Two mechanical detectors fall straight out of it, and neither passes through the agent’s self-assessment.

The first: a run that ended at its iteration limit. That would have fired on August 6, five days early. The second, and the one that matters more: a whole-file read against a file bigger than the ceiling. Pure arithmetic — the trace has the path, the filesystem has the size, and severity is one minus the ratio. That one catches the case that produces no symptom at all.

07 — what changed

Four things, and an alarm

Test: documents meant to be read whole must fit The alarm that was missing

On the same prompt, the run went from eight iterations to three, twelve calls to six, none of them on the calendar, and $0.28 to $0.10 — finishing on its own instead of being cut off. It spent the freed turns on the repositories, where it noticed that a task two weeks overdue had actually shipped: a contradiction between the calendar and the commit log that the calendar alone can never surface.

08 — one more

The fix broke the fix

Setting both ceilings to the same number destroyed the thing they exist for. A truncated read is the file prefix plus the notice, which pushed the result over the universal clip, which cut the notice off and replaced it with a generic one.

The informative message would have been destroyed in exactly the case it exists for. A test caught it about a minute after being written — and taught the lesson twice, because the failure mode of a clip is always that it removes the evidence of itself.

fin

None of this needed an unusual setup. A read tool with a byte limit and a file that grows is the entire recipe. The only thing that made it visible was a decision log nobody had thought to query that way — and a bad brief, on a Tuesday, that was wrong about itself in a way that turned out to be worth chasing.
